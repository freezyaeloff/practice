В ходе практики исследовано влияние загрузки CPU отправителя и приёмника на скорость передачи и потери UDP-пакетов.

Условия проведения: Linux в WSL2. Передача выполнялась через `127.0.0.1`, размер данных одной UDP датаграммы 1200 байт. Отправитель закреплён за CPU 0, приёмник за CPU 1, захват пакетов и мониторинг за CPU 2. Фактический размер приёмного буфера сокета равен 8192 байтам. 

Проверены скорости 1, 3, 5, 7 и 10 Мбит/с. Для каждой скорости проведены три повтора длительностью 60 секунд в четырёх условиях:

- `baseline` - без дополнительной нагрузки
- `tx-cpu` - нагрузка на CPU отправителя
- `rx-cpu` - нагрузка на CPU приёмника
- `both-cpu` - нагрузка на оба CPU

Всего выполнено 60 опытов. Нагрузка создавалась четырьмя worker процессами `stress-ng` на каждом нагружаемом CPU. По данным мониторинга средняя занятость нагружаемых CPU во время передачи составила 100%

**Результаты наблюдений**

Без дополнительной нагрузки потери не обнаружены на всех проверенных скоростях. Фактическая скорость отправки соответствовала заданной. При увеличении скорости с 1 до 10 Мбит/с средняя загрузка CPU отправителя выросла примерно с 0,36% до 8,08%, приёмника - с 0,09% до 1,68%.

При нагрузке только на CPU отправителя потери доставки также не обнаружены. Однако начиная с заданных 3 Мбит/с отправитель пропускал запланированные слоты отправки, поэтому фактическая скорость снижалась. При заданных 10 Мбит/с она составила в среднем 9,286 Мбит/с. Неотправленные пакеты не учитывались как потери доставки.

При нагрузке только на CPU приёмника на скоростях 1–7 Мбит/с потери не обнаружены. На 10 Мбит/с потери появились во всех трёх повторах: 357, 364 и 387 пакетов. Суммарно потеряно 1108 из 187 500 отправленных пакетов - 0,59093%.

При одновременной нагрузке на оба CPU потери не обнаружены на скоростях 1, 3 и 5 Мбит/с. На 7 Мбит/с потеряно два пакета: по одному в двух из трёх повторов. На 10 Мбит/с потеряно 611 из 177 565 отправленных пакетов - 0,34410%. Средняя фактическая скорость отправки при этом составила 9,470 Мбит/с.

Нагрузка на CPU отправителя прежде всего снижала фактический темп отправки, а нагрузка на CPU приёмника при высокой скорости сопровождалась сбросами пакетов приёмного сокета. При нагрузке обоих CPU на 10 Мбит/с потерь оказалось меньше, чем при нагрузке только приёмника, но одновременно была ниже и фактическая скорость отправки.
